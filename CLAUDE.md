# CLAUDE.md

This repo holds `templates/terraform/` — versioned, reusable Terraform modules (Scaleway), merged in from the former `pigeon-tf` repo (ADR-0037) and `pigeon-do` repo (ADR-0052), moved to top-level `modules/` from `terraform/modules/` by ADR-0093, then to this location by ADR-0110 (which also kept the `noisypigeon.com/modules/<provider>/<module>/vX.Y.Z` short import URLs from ADR-0109 unchanged, decoupling that public namespace from the directory's actual location going forward) — `templates/zola-site/`, a reusable Zola theme extracted from the blog's own engine once it turned out to already be almost entirely generic (ADR-0112), consumed by a committed relative symlink at `workloads/blog/src/themes/zola-site` rather than a vendored copy, and versioned via its own `templates/zola-site/vX.Y.Z` git tags (ADR-0113), seeded at `v1.0.0` since the engine was already production code at the time it first became releasable — pinnable per-consumer via `[extra].theme_version` and `resolve-theme.sh` (ADR-0114), with `workloads/blog/src` itself left on live-tracking `"main"` — and `workloads/`, where each workload gets its own `workloads/<name>/` directory (`src/` for its content, `terraform/` for the infrastructure it's part of — colocated, not provider-rooted). `workloads/` is this repo's only live Terragrunt/Terraform tree: the former provider-rooted `terraform/infrastructure/` was fully decommissioned once its last two leaves moved into `workloads/custodian-buckets/terraform/` (ADR-0098), which also added a `workload_definition.hcl`-based per-leaf Scaleway region/zone override mechanism to `workloads/root.hcl` (every leaf defaults to `fr-par`; the `nl-ams` `duck-jellyfish` leaf, now at `workloads/scaleway/terraform/custodian/duck-jellyfish` per ADR-0106, is the first and so far only `nl-ams` leaf). The blog lives at `workloads/blog/`: `src/` is a Zola-based static site for the personal blog at `noisypigeon.com`, rewritten from Jekyll (ADR-0067) and moved from `service/blog/` into this convention (ADR-0091) — `workloads/blog/` is now `src/`-only, since its `terraform/` leaf (the Cloudflare DNS records pointing `noisypigeon.com` at GitHub Pages, originally moved from `terraform/infrastructure/` by ADR-0092, which also added `workloads/root.hcl` and moved the shared `.env` to the true repo root) relocated into `workloads/dns/` by ADR-0105. The blog also has its own `workloads/blog/CHANGELOG.md` (rolling up into the root `CHANGELOG.md` under `[blog]`) and an on-site `/changelog/` channel backed by a real `src/content/changelog/` section — both wired up by ADR-0107, which extended `.github/workflows/module-release.yml` to fire on blog PR merges (no `release:*` label, no version/tag), mirror each day's blog changelog entries onto an auto-generated daily digest post, and fixed the workflow's date stamp from UTC to `America/Los_Angeles`. `workloads/scaleway/terraform/` groups every Scaleway-specific leaf not already owned by a more specific workload — today just `custodian/duck-jellyfish/`, the `nl-ams` cross-region backup bucket moved in from the former standalone `workloads/custodian-buckets/` workload (ADR-0098) by ADR-0106, which also found `custodian-buckets/terraform/duck-jellyfish-import` (the `fr-par` source-side sibling) had already been deleted outright in an earlier, separate change — leaving `duck-jellyfish` as `custodian-buckets/`'s only leaf and decommissioning that workload entirely once it moved. `management/` (this repo's own Terraform state bucket and deployer IAM application/policy/API key, the identity every other Scaleway leaf authenticates as) lived here too — moved to `workloads/scaleway/terraform/` by ADR-0094, into a `management/` subdirectory by ADR-0106 — until ADR-0124 promoted it to its own top-level workload, `workloads/management/terraform/scaleway/` (the `scaleway/` segment leaving room for a future non-Scaleway management leaf without a second move). `pigeon-cli/cockpit/` (the shared Cockpit metrics/logs source and push token for every `pigeon-cli` compute instance, ADR-0103) and `pigeon-cli/iam-application/` (the shared IAM application every `pigeon-cli` job policy attaches to, ADR-0119) likewise lived here, nested by owning workload rather than by purpose (ADR-0106/0115) — ADR-0124 moved both the rest of the way, into `workloads/pigeon-cli/terraform/shared/`, alongside the `job/` leaf that actually consumes their outputs. `workloads/bucket/terraform/` is a second, purpose-rooted (not provider-rooted) grouping alongside `workloads/scaleway/terraform/`, holding storage-bucket infrastructure grouped by **dataset** rather than by consumer (ADR-0117, regrouping ADR-0116's consumer-first `pigeon-cli/{import,deduplication}/*` shape): under `noisypigeon/`, each dataset collocates its `import/` and/or `deduplication/` leaf as siblings — `backblaze/import`, `email/import`, `macbook-scratch/deduplication`, `media/deduplication`, and `poisoned/{computer-snapshots,mega-storage-consolidation,t7-backup}/{import,deduplication}` (the three `poisoned/*` datasets have both). Only `poisoned/mega-storage-consolidation/deduplication` actually has a compute instance/volume/IAM policy; every other leaf (9 of 10) is bucket-only. Every leaf's underlying Scaleway resource name stays untouched across both ADR-0116 and ADR-0117 — only the repo path changed, even where a directory rename no longer exactly matches its real resource name (`poisoned-mega-consolidation`, deliberately, to avoid replacing a live compute instance). One pre-scaffolded placeholder, `noisypigeon/macbook-scratch/import/`, has no corresponding leaf and sits empty, presumably for separate future work. `workloads/dns/terraform/` groups every Cloudflare-managed DNS leaf by domain: `{noisypigeon.com,pigeon.dev}/fastmail/` (each domain's Fastmail SPF/DKIM/MX records, originally moved to `workloads/email/terraform/fastmail/<domain>/` by ADR-0096 — which also widened `workloads/root.hcl`'s leaf-depth convention to admit nesting beyond `<name>/terraform` and folded in `pigeon.dev`'s move onto the same Cloudflare account as `noisypigeon.com` — then relocated again into this domain-first layout by ADR-0105), `noisypigeon.com/bluesky/` (the AT Protocol domain-handle verification TXT record, moved from `workloads/bluesky/terraform/noisypigeon.com/` by ADR-0105), `noisypigeon.com/blog/` (the GitHub Pages DNS leaf moved from `workloads/blog/terraform/`, also by ADR-0105), and `pigeon.dev/redirect/` (a new leaf, added by ADR-0105, redirecting `pigeon.dev` apex + `www` to `https://noisypigeon.com` via a `cloudflare_ruleset` on the `http_request_dynamic_redirect` phase — Cloudflare v5 removed `cloudflare_page_rule` — plus placeholder proxied DNS records, since `pigeon.dev` otherwise has no apex/`www` record for Cloudflare's edge to intercept). With both `fastmail` and `bluesky` moved out, ADR-0105 decommissioned `workloads/email/` and `workloads/bluesky/` entirely. `workloads/pigeon-cli/` — originally holding `terraform/{import,deduplication}/*`, moved there from `terraform/infrastructure/scaleway/fr-par/{noisypigeon/import/*,pigeon/deduplication/macbook-scratch}` by ADR-0097 — had both of those groups relocated out (to `workloads/bucket/terraform/pigeon-cli/` by ADR-0116 (amended), then regrouped again by dataset under `workloads/bucket/terraform/noisypigeon/` by ADR-0117), fully decommissioning it; it was later reoccupied by `terraform/job/` (the `pigeon-cli` compute-instance job leaf, composing `compute-instance`'s `iam_config`/`block_volume` per ADR-0118/0120/0122) and, by ADR-0124, `terraform/shared/{cockpit,iam-application}` (moved in from `workloads/scaleway/terraform/pigeon-cli/`, see above) — `pigeon-cli` still has no `src/` in this repo, having split out entirely via ADR-0084. `service/pigeon-cli` (the `pigeon` Rust CLI) split out of this repo into its own, `noisypigeon/pigeon-cli`, via ADR-0084 — that ADR (and this repo's full pre-split, pigeon-cli-only ADR/report history) was deleted from this repo once no longer needed here; it survives only in `noisypigeon/pigeon-cli`.

## ADRs govern this project

Before making architectural or interface changes, read the ADRs in `docs/adr/` and keep new work consistent with their decisions. If a change would contradict an existing ADR, flag it rather than silently diverging — prefer writing a new ADR (or updating an existing one's Status) over undocumented drift. Every surviving terraform/blog-relevant ADR from before the `service/pigeon-cli` split lives flat in `docs/adr/` alongside everything after it (renumbered inline per ADR-0037/ADR-0052, not archived separately); the pigeon-cli-only ADRs were deleted once that code moved to `noisypigeon/pigeon-cli` (which maintains its own copy) — the list below is what's actually live and binding in this repo going forward.

- `docs/adr/0038-pigeon-tf-scaffold.md` — (originally `pigeon-tf` ADR-0001) repo layout, module self-containment (per-module `versions.tf`), versioning/tagging, and local-clone consumption model, now for `terraform/modules/`.

- `docs/adr/0069-guard-scaleway-iam-policy-bucket-policy-self-lockout.md` — root-causes a real incident: `iam-policy`'s bucket-scoped `scaleway_object_bucket_policy` names only the freshly-minted narrow application, and Scaleway's allow-only bucket-policy model then locks the deployer itself out of the bucket (confirmed applying against `noisypigeon/cli/scratch`, recoverable only via out-of-band owner credentials). Adds an `admin_project_id` variable so the deployer identity is always also granted.
- `docs/adr/0070-fix-scaleway-iam-policy-admin-statement-deprecated-version.md` — ADR-0069's generated admin statement used the module's existing policy `Version`, which Scaleway rejected outright on the first live `tofu apply` (`v1.1.0` against `noisypigeon/cli/scratch`). Fixes the version.
- `docs/adr/0072-fix-scaleway-object-bucket-glacier-transition-minimum-days.md` — root-causes `object-bucket`'s `storage_class = "glacier"` failing outright on its one live consumer (`noisypigeon/vault/email`): ADR-0044 designed it as an immediate (`days = 0`) transition, but Scaleway enforces a 90-day minimum. Fixes the module to respect it.
- `docs/adr/0079-add-scaleway-compute-instance-module.md` — adds `terraform/modules/scaleway/compute-instance`, a deliberately minimal wrapper around `scaleway_instance_server` — unlike `digitalocean/droplet`'s bundled cloud-init/rclone/SSH-key/Cloudflare-DNS machinery, none of which is wanted yet for Scaleway.

## Dev cycle

Terraform module changes follow their own PR discipline — see the `release-pr` Claude Code skill and `templates/terraform/README.md`. There is no crate-style `mise run ci` gate in this repo (that was `service/pigeon-cli`-specific, ADR-0029, and now lives with it in `noisypigeon/pigeon-cli`).

When an ADR's `## Out of scope` section has a genuinely-deferred item (not a permanent design boundary), file it via `mise run adr-issue` while landing that ADR — reuse an existing `out-of-scope`-labeled issue with `--issue N` if the same gap was already raised elsewhere. See `docs/adr/0031-out-of-scope-issue-tracking.md`.

## Commands

- `mise run fmt-terraform` / `mise run fmt-check-terraform` — format / check formatting for Terraform and Terragrunt files.
- `mise run plan` / `mise run apply` — `terragrunt run --all -- plan`/`apply` across `workloads/`.
- `mise run blog-build` / `mise run blog-serve` — build / serve `workloads/blog/src` with Zola.
- `mise run adr-issue -- <args>` — file (or reuse) a GitHub issue for an ADR's Out of scope bullet and link it back into the ADR.
