# CLAUDE.md

This repo holds `modules/` — versioned, reusable Terraform modules (Scaleway), merged in from the former `pigeon-tf` repo (ADR-0037) and `pigeon-do` repo (ADR-0052), moved to this top-level location from `terraform/modules/` by ADR-0093 — plus `terraform/infrastructure/`, this repo owner's live Terragrunt/Terraform configuration consuming those modules, and `workloads/`, where each workload gets its own `workloads/<name>/` directory (`src/` for its content, `terraform/` for the infrastructure it's part of — colocated, not provider-rooted). The blog lives at `workloads/blog/`: `src/` is a Zola-based static site for the personal blog at `noisypigeon.com`, rewritten from Jekyll (ADR-0067) and moved from `service/blog/` into this convention (ADR-0091); `terraform/` is the Cloudflare DNS leaf pointing `noisypigeon.com` at GitHub Pages, moved from `terraform/infrastructure/` (ADR-0092), which also added `workloads/root.hcl` and moved the shared `.env` to the true repo root. `workloads/scaleway/terraform/` is this repo's own Terraform state bucket and deployer IAM application/policy/API key — every other `scaleway/*` leaf authenticates as that identity — moved there by ADR-0094, which also extended `workloads/root.hcl` with Scaleway provider wiring. `service/pigeon-cli` (the `pigeon` Rust CLI) split out of this repo into its own, `noisypigeon/pigeon-cli`, via ADR-0084 — that ADR (and this repo's full pre-split, pigeon-cli-only ADR/report history) was deleted from this repo once no longer needed here; it survives only in `noisypigeon/pigeon-cli`.

## ADRs govern this project

Before making architectural or interface changes, read the ADRs in `docs/adr/` and keep new work consistent with their decisions. If a change would contradict an existing ADR, flag it rather than silently diverging — prefer writing a new ADR (or updating an existing one's Status) over undocumented drift. Every surviving terraform/blog-relevant ADR from before the `service/pigeon-cli` split lives flat in `docs/adr/` alongside everything after it (renumbered inline per ADR-0037/ADR-0052, not archived separately); the pigeon-cli-only ADRs were deleted once that code moved to `noisypigeon/pigeon-cli` (which maintains its own copy) — the list below is what's actually live and binding in this repo going forward.

- `docs/adr/0037-merge-pigeon-tf-terraform-modules.md` — merges the separate `pigeon-tf` repo's full history into this repo as `terraform/modules/{digitalocean,scaleway}/*`, via a `git filter-repo` path rewrite (preserving all 20 release tags on their rewritten commits) plus `git merge --allow-unrelated-histories`; its 12 ADRs join `docs/adr/` renumbered to 0038-0049 with an added Origin bullet each; its two GitHub Actions workflows and one Claude Code skill (`.github/workflows/`, `.claude/skills/release-pr/`) move over unchanged in path but retargeted at the new module paths; its README becomes `terraform/README.md` and its CLAUDE.md folds into this file.
- `docs/adr/0038-pigeon-tf-scaffold.md` — (originally `pigeon-tf` ADR-0001) repo layout, module self-containment (per-module `versions.tf`), versioning/tagging, and local-clone consumption model, now for `terraform/modules/`.
- `docs/adr/0043-add-scaleway-provider.md` — (originally `pigeon-tf` ADR-0006) adds the second provider root (`terraform/modules/scaleway/`), generalizes `module-docs.yml`/`module-release.yml` beyond a single hardcoded provider root, and fixes a latent per-module tag-naming bug.
- `docs/adr/0052-merge-pigeon-do-terraform-infrastructure.md` — decides how to merge the separate `pigeon-do` repo's full history into this repo as `terraform/infrastructure/*` (a new sibling to `terraform/modules/`), renumbering its 12 ADRs to 0053-0064, rewriting its `git::.../pigeon-tf.git//...` module sources to `.../pigeon.git//terraform/modules/...`, and folding its `.mise.toml`/`.gitignore`/`CLAUDE.md` into this repo's — a decision record only; the user performs the actual merge manually given the repo's live-infrastructure content.
- `docs/adr/0066-scaleway-iam-policy-prevent-bucket-scope-widening.md` — root-causes why `terraform/modules/scaleway/iam-policy`'s bucket-scoped `bucket_names`/`bucket_actions` never actually worked in its one real prior use: a blanket `ObjectStorage*` grant composed with it made `bucket_names` decorative, exactly the composition hazard ADR-0048 anticipated but chose not to guard against. Adds the guard.
- `docs/adr/0067-rewrite-blog-to-zola.md` — rewrites the standalone `noisypigeon.github.io` Jekyll blog as `service/blog` (since renamed to `workloads/blog/src`, ADR-0091), a Zola site with byte-identical CSS/assets/HTML structure (syntax highlighting deliberately left off, matching today's unstyled code blocks); content is copied in fresh rather than history-merged; concludes the Cloudflare DNS records in `terraform/infrastructure/cloudflare/global/noisypigeon.com/github/` need **no changes** (GitHub Pages' custom-domain-to-repo mapping is account-level, not DNS-based) — only a manual GitHub Pages settings cutover, performed by the user.
- `docs/adr/0069-guard-scaleway-iam-policy-bucket-policy-self-lockout.md` — root-causes a real incident: `iam-policy`'s bucket-scoped `scaleway_object_bucket_policy` names only the freshly-minted narrow application, and Scaleway's allow-only bucket-policy model then locks the deployer itself out of the bucket (confirmed applying against `noisypigeon/cli/scratch`, recoverable only via out-of-band owner credentials). Adds an `admin_project_id` variable so the deployer identity is always also granted.
- `docs/adr/0070-fix-scaleway-iam-policy-admin-statement-deprecated-version.md` — ADR-0069's generated admin statement used the module's existing policy `Version`, which Scaleway rejected outright on the first live `tofu apply` (`v1.1.0` against `noisypigeon/cli/scratch`). Fixes the version.
- `docs/adr/0072-fix-scaleway-object-bucket-glacier-transition-minimum-days.md` — root-causes `object-bucket`'s `storage_class = "glacier"` failing outright on its one live consumer (`noisypigeon/vault/email`): ADR-0044 designed it as an immediate (`days = 0`) transition, but Scaleway enforces a 90-day minimum. Fixes the module to respect it.
- `docs/adr/0079-add-scaleway-compute-instance-module.md` — adds `terraform/modules/scaleway/compute-instance`, a deliberately minimal wrapper around `scaleway_instance_server` — unlike `digitalocean/droplet`'s bundled cloud-init/rclone/SSH-key/Cloudflare-DNS machinery, none of which is wanted yet for Scaleway.
- `docs/adr/0081-add-cloud-init-rclone-bucket-access-to-scaleway-compute-instance.md` — ports `digitalocean/droplet`'s rclone/neovim cloud-init provisioning and bucket-configured `rclone.conf` to `scaleway/compute-instance`, keeping bucket-scoped access-key creation an external `scaleway/iam-policy` composition rather than pulling it into the module.
- `docs/adr/0085-add-scaleway-block-volume-module.md` — adds `terraform/modules/scaleway/block-volume`, a minimal wrapper around `scaleway_block_volume` (required `size`, renamed from `size_in_gb`; `iops` defaults to `15000`), and extends `scaleway/compute-instance` with a pass-through `additional_volume_ids` input so callers can attach a volume without either module composing the other internally.
- `docs/adr/0086-decommission-digitalocean.md` — documents the completed migration off DigitalOcean once Scaleway module parity landed: deletes all 6 `terraform/modules/digitalocean/*` modules and the remaining `terraform/infrastructure/digitalocean/*` leaves, leaving Scaleway + Cloudflare as this repo's only providers, and fixes the prose docs/CI workflows (`module-release.yml`, `module-docs.yml`) that still described the now-deleted DigitalOcean surface.
- `docs/adr/0091-rename-service-blog-to-workloads-blog-src.md` — renames `service/blog/` to `workloads/blog/src/`, establishing a `workloads/<name>/src/` convention for future non-Terraform workloads beyond the blog (the `src/` leaves room for future sibling directories per workload); updates `.gitignore`, `.mise.toml`'s `blog-build`/`blog-serve` tasks, and the live `blog-pages.yml` GitHub Pages deploy workflow.
- `docs/adr/0092-move-github-pages-leaf-to-workloads-blog-terraform.md` — moves the Cloudflare DNS leaf for GitHub Pages from `terraform/infrastructure/cloudflare/global/noisypigeon.com/github/` to `workloads/blog/terraform/`, the first leaf of a terraform-colocated-with-its-workload convention (alongside `terraform/infrastructure/`'s provider-rooted one); adds `workloads/root.hcl`, which enforces `workloads/*/terraform` via Terragrunt's `exclude` block; also moves the shared `.env`/`.env.example` from `terraform/infrastructure/` to the true repo root so both Terragrunt trees can reach it.
- `docs/adr/0093-move-scaleway-modules-to-top-level-modules.md` — moves `terraform/modules/scaleway/*` to top-level `modules/scaleway/*` and cuts a major release for every module (`project`/`object-bucket`/`compute-instance` → v1.0.0, `iam-policy`/`block-volume` → v2.0.0, since both were already past 1.0), fixing the stale `noisypigeon/pigeon.git` repo name in every source string along the way; updates all 16 live consumer leaves, `module-release.yml`/`module-docs.yml`, the `release-pr` skill, and deletes `terraform/README.md`.
- `docs/adr/0094-move-scaleway-bootstrap-leaf-to-workloads.md` — moves the Scaleway bootstrap leaf (this repo's own Terraform state bucket + deployer IAM application/policy/API key) from `terraform/infrastructure/scaleway/fr-par/noisypigeon/terraform/` to `workloads/scaleway/terraform/` as a pure state-key relocation, not a resource change — extends `workloads/root.hcl` with Scaleway provider wiring (previously Cloudflare-only); the actual `terragrunt init` state copy is a manual step left for the user, not performed by this ADR.

## Dev cycle

Terraform module changes follow their own PR discipline — see the `release-pr` Claude Code skill and `modules/README.md`. There is no crate-style `mise run ci` gate in this repo (that was `service/pigeon-cli`-specific, ADR-0029, and now lives with it in `noisypigeon/pigeon-cli`).

When an ADR's `## Out of scope` section has a genuinely-deferred item (not a permanent design boundary), file it via `mise run adr-issue` while landing that ADR — reuse an existing `out-of-scope`-labeled issue with `--issue N` if the same gap was already raised elsewhere. See `docs/adr/0031-out-of-scope-issue-tracking.md`.

## Commands

- `mise run fmt-terraform` / `mise run fmt-check-terraform` — format / check formatting for Terraform and Terragrunt files.
- `mise run plan` / `mise run apply` — `terragrunt run --all -- plan`/`apply` across `terraform/infrastructure/`.
- `mise run blog-build` / `mise run blog-serve` — build / serve `workloads/blog/src` with Zola.
- `mise run adr-issue -- <args>` — file (or reuse) a GitHub issue for an ADR's Out of scope bullet and link it back into the ADR.
