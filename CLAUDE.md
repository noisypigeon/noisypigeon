# CLAUDE.md

This repo holds `templates/terraform/` — versioned, reusable Terraform modules (Scaleway), merged in from the former `pigeon-tf` repo (ADR-0037) and `pigeon-do` repo (ADR-0052), moved to top-level `modules/` from `terraform/modules/` by ADR-0093, then to this location by ADR-0110 (which also kept the `noisypigeon.com/modules/<provider>/<module>/vX.Y.Z` short import URLs from ADR-0109 unchanged, decoupling that public namespace from the directory's actual location going forward) — and `workloads/`, where each workload gets its own `workloads/<name>/` directory (`src/` for its content, `terraform/` for the infrastructure it's part of — colocated, not provider-rooted). `workloads/` is this repo's only live Terragrunt/Terraform tree: the former provider-rooted `terraform/infrastructure/` was fully decommissioned once its last two leaves moved into `workloads/custodian-buckets/terraform/` (ADR-0098), which also added a `workload_definition.hcl`-based per-leaf Scaleway region/zone override mechanism to `workloads/root.hcl` (every leaf defaults to `fr-par`; the `nl-ams` `duck-jellyfish` leaf, now at `workloads/scaleway/terraform/custodian/duck-jellyfish` per ADR-0106, is the first and so far only `nl-ams` leaf). The blog lives at `workloads/blog/`: `src/` is a Zola-based static site for the personal blog at `noisypigeon.com`, rewritten from Jekyll (ADR-0067) and moved from `service/blog/` into this convention (ADR-0091) — `workloads/blog/` is now `src/`-only, since its `terraform/` leaf (the Cloudflare DNS records pointing `noisypigeon.com` at GitHub Pages, originally moved from `terraform/infrastructure/` by ADR-0092, which also added `workloads/root.hcl` and moved the shared `.env` to the true repo root) relocated into `workloads/dns/` by ADR-0105. The blog also has its own `workloads/blog/CHANGELOG.md` (rolling up into the root `CHANGELOG.md` under `[blog]`) and an on-site `/changelog/` channel backed by a real `src/content/changelog/` section — both wired up by ADR-0107, which extended `.github/workflows/module-release.yml` to fire on blog PR merges (no `release:*` label, no version/tag), mirror each day's blog changelog entries onto an auto-generated daily digest post, and fixed the workflow's date stamp from UTC to `America/Los_Angeles`. `workloads/scaleway/terraform/` groups every Scaleway-specific leaf: `management/` is this repo's own Terraform state bucket and deployer IAM application/policy/API key — every other `scaleway/*` leaf authenticates as that identity — moved to `workloads/scaleway/terraform/` by ADR-0094 (which also extended `workloads/root.hcl` with Scaleway provider wiring), then into this `management/` subdirectory by ADR-0106; `custodian/duck-jellyfish/` is the `nl-ams` cross-region backup bucket, moved in from the former standalone `workloads/custodian-buckets/` workload (ADR-0098) by that same ADR-0106, which also found `custodian-buckets/terraform/duck-jellyfish-import` (the `fr-par` source-side sibling) had already been deleted outright in an earlier, separate change — leaving `duck-jellyfish` as `custodian-buckets/`'s only leaf and decommissioning that workload entirely once it moved. `workloads/dns/terraform/` groups every Cloudflare-managed DNS leaf by domain: `{noisypigeon.com,pigeon.dev}/fastmail/` (each domain's Fastmail SPF/DKIM/MX records, originally moved to `workloads/email/terraform/fastmail/<domain>/` by ADR-0096 — which also widened `workloads/root.hcl`'s leaf-depth convention to admit nesting beyond `<name>/terraform` and folded in `pigeon.dev`'s move onto the same Cloudflare account as `noisypigeon.com` — then relocated again into this domain-first layout by ADR-0105), `noisypigeon.com/bluesky/` (the AT Protocol domain-handle verification TXT record, moved from `workloads/bluesky/terraform/noisypigeon.com/` by ADR-0105), `noisypigeon.com/blog/` (the GitHub Pages DNS leaf moved from `workloads/blog/terraform/`, also by ADR-0105), and `pigeon.dev/redirect/` (a new leaf, added by ADR-0105, redirecting `pigeon.dev` apex + `www` to `https://noisypigeon.com` via a `cloudflare_ruleset` on the `http_request_dynamic_redirect` phase — Cloudflare v5 removed `cloudflare_page_rule` — plus placeholder proxied DNS records, since `pigeon.dev` otherwise has no apex/`www` record for Cloudflare's edge to intercept). With both `fastmail` and `bluesky` moved out, ADR-0105 decommissioned `workloads/email/` and `workloads/bluesky/` entirely. `workloads/pigeon-cli/terraform/` holds infrastructure backing the external `pigeon` CLI's jobs — three `import/` object-storage buckets (`backblaze`, `macbook-scratch`, `email`) and one `deduplication/macbook-scratch` leaf (compute instance + block volume + bucket) — moved there from `terraform/infrastructure/scaleway/fr-par/{noisypigeon/import/*,pigeon/deduplication/macbook-scratch}` by ADR-0097, which needed no `workloads/root.hcl` changes at all (every local these leaves need was already wired by ADR-0094/0096). `service/pigeon-cli` (the `pigeon` Rust CLI) split out of this repo into its own, `noisypigeon/pigeon-cli`, via ADR-0084 — that ADR (and this repo's full pre-split, pigeon-cli-only ADR/report history) was deleted from this repo once no longer needed here; it survives only in `noisypigeon/pigeon-cli`.

## ADRs govern this project

Before making architectural or interface changes, read the ADRs in `docs/adr/` and keep new work consistent with their decisions. If a change would contradict an existing ADR, flag it rather than silently diverging — prefer writing a new ADR (or updating an existing one's Status) over undocumented drift. Every surviving terraform/blog-relevant ADR from before the `service/pigeon-cli` split lives flat in `docs/adr/` alongside everything after it (renumbered inline per ADR-0037/ADR-0052, not archived separately); the pigeon-cli-only ADRs were deleted once that code moved to `noisypigeon/pigeon-cli` (which maintains its own copy) — the list below is what's actually live and binding in this repo going forward.

- `docs/adr/0072-fix-scaleway-object-bucket-glacier-transition-minimum-days.md` — root-causes `object-bucket`'s `storage_class = "glacier"` failing outright on its one live consumer (`noisypigeon/vault/email`): ADR-0044 designed it as an immediate (`days = 0`) transition, but Scaleway enforces a 90-day minimum. - `docs/adr/0107-wire-blog-into-changelog-workflow.md` — extends `.github/workflows/module-release.yml` (previously hardcoded to `modules/scaleway/*` via a `versions.tf`/`.tf`-file check) with a parallel, unversioned blog path: a merged PR touching `workloads/blog/src/` gets a dated entry in a new `workloads/blog/CHANGELOG.md`, a `[blog]` one-liner rollup in the root `CHANGELOG.md`, and an idempotent append to an auto-generated daily digest post at `src/content/changelog/YYYY-MM-DD-changelog.md` (one post per day with blog changelog activity, blog-scoped only — not the whole repo's module/pigeon-cli activity); no `release:*` label needed since the blog isn't tagged/released. Separately restructures the on-site changelog: the 4 posts previously tagged `[extra]\npost_type = "changelog"` physically move from `content/posts/` into a real `content/changelog/` section (renumbered `0001`-`0004`, `aliases` added so their old `/posts/<slug>/` URLs still resolve), `content/posts/` renumbered `0001`-`0053` to close the resulting gaps, and both changelog templates/section config updated accordingly (slug-driven permalinks confirmed unaffected by any renumbering). A small follow-up CI fix (PR #137, no ADR) made `module-release.yml` explicitly dispatch `blog-pages.yml` after its bot-authored changelog commits, since pushes made with the default `GITHUB_TOKEN` don't trigger other workflows' `push` events.
- `docs/adr/0108-backfill-blog-changelog-history.md` — computes the daily digest post's title from its actual entries (strips a leading conventional-commit prefix off the chronologically-first entry, collapsing additional same-day entries into a `(+N more)` suffix) instead of the prior hardcoded `"Changelog: ${TODAY}"`; and backfills `workloads/blog/CHANGELOG.md`, 10 new root-`CHANGELOG.md` `[blog]` one-liners, and on-site digest posts for `2026-09-27`/`2026-10-01`/`2026-10-03` — the small, concrete 12-commit window between the blog's existence in this repo and ADR-0107's automation landing (two incidentally-blog-touching commits, PR #135 and PR #119, excluded as out of the automation's own path-filter scope; PR #66's pre-existing root-`CHANGELOG.md` entry left untouched per this repo's established no-rewrite-history precedent).
- `docs/adr/0109-short-module-source-urls-via-blog-redirect.md` — adds short `noisypigeon.com/modules/<provider>/<module>/vX.Y.Z` module import URLs, resolved via Terraform/go-getter's HTTP module-source discovery protocol (`?terraform-get=1` → a `<meta name="terraform-get">` tag) to a static redirect page generated per module-version git tag by a new `workloads/blog/generate-module-redirects.sh` (wired into `blog-build`/`blog-serve` and `blog-pages.yml`); migrates all 22 existing `workloads/**/*.tf` consumer `source =` lines to the short form (non-breaking — old `git::` sources keep working); `module-release.yml` now also triggers a blog deploy whenever a module is tagged, not just on direct blog-file changes.
- `docs/adr/0110-move-modules-to-templates-terraform.md` — moves `modules/scaleway/*` to `templates/terraform/scaleway/*`, establishing `templates/` as a new top-level convention; the ADR-0109 short URLs stay unchanged throughout, since the generator script's public URL path is hardcoded independent of which tag prefix a module's version actually lives under — the entire point of landing ADR-0109 first. Following ADR-0093's direct precedent (a module's source path is part of its public interface; moving it is breaking regardless of content changes), cuts a major-version seed tag for every module under the new prefix. Zero `workloads/**/*.tf` consumer changes needed, unlike ADR-0093's 16-consumer rewrite — the redirect layer already absorbed that breaking surface. Landed as two sequential PRs (pure file move first, workflow/doc updates second) to avoid the automated release pipeline misreading the renamed `.tf` files as "module content changed" and auto-tagging every module at a bogus `v0.1.0`.

## Dev cycle

Terraform module changes follow their own PR discipline — see the `release-pr` Claude Code skill and `templates/terraform/README.md`. There is no crate-style `mise run ci` gate in this repo (that was `service/pigeon-cli`-specific, ADR-0029, and now lives with it in `noisypigeon/pigeon-cli`).

When an ADR's `## Out of scope` section has a genuinely-deferred item (not a permanent design boundary), file it via `mise run adr-issue` while landing that ADR — reuse an existing `out-of-scope`-labeled issue with `--issue N` if the same gap was already raised elsewhere. See `docs/adr/0031-out-of-scope-issue-tracking.md`.

## Commands

- `mise run fmt-terraform` / `mise run fmt-check-terraform` — format / check formatting for Terraform and Terragrunt files.
- `mise run plan` / `mise run apply` — `terragrunt run --all -- plan`/`apply` across `workloads/`.
- `mise run blog-build` / `mise run blog-serve` — build / serve `workloads/blog/src` with Zola.
- `mise run adr-issue -- <args>` — file (or reuse) a GitHub issue for an ADR's Out of scope bullet and link it back into the ADR.
